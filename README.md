# 競馬予想AI Prototype v0.2（Phase A）

応募時に「サンプルデータ生成から画面表示まで、一連の機械学習プロトタイプを開発できる」ことを示すための小さな完成見本です。固定random seedで作る架空データを使い、前処理、LightGBM学習、時系列評価、Streamlit表示までを再現できます。

> **重要:** このプロジェクトは架空のサンプルデータによる技術デモです。実在レースの予測や、実運用で通用する精度を示すものではありません。

## 現在できること

- 固定seedによる架空の複数日・複数レースデータの生成
- 予想時点で利用可能な特徴量の前処理
- LightGBMによる各出走馬の1着／非1着の二値分類
- 日付順のtrain → valid → test時系列3分割と、ROC-AUC・Log Loss・Top-pick accuracyの算出（testはモデル調整に使用しない）
- 予想時点オッズから求めた市場暗黙確率との比較
- testレースを日付で絞り込んで選べるStreamlit画面
- testレースに対する購入シミュレーション（AI予想1位 / 1番人気それぞれの的中率・回収率・レース単位bootstrapによる95%信頼区間）の算出（架空データ上のシミュレーションであり、実競馬での収益性を示すものではない）
- AI予想1位の表示勝率平均と実際の勝率の差による、確率較正状態の確認
- 同一データ・同一分割でのLightGBM旧設定／新設定の比較（`--compare`。新設定の採否はvalidの指標のみで判定）

## 現在できないこと

- 実在する馬・レースの予測
- JRA-VAN / JV-Linkとの接続
- Webサイトのスクレイピングや実データ取得
- 自動的な予想ルール変更
- 馬券の購入判断・購入記録・購入処理
- 実運用レベルの精度保証

## セットアップ

Windows PowerShellでプロジェクトフォルダへ移動し、Python 3.12の仮想環境を使用します。

```powershell
cd keiba-ai-prototype
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

すでに `.venv` とライブラリが用意されている場合、再作成や再インストールは不要です。グローバルPythonへインストールする必要はありません。

## 実行方法

### 1. サンプルデータ生成

```powershell
.venv\Scripts\python.exe src\generate_sample_data.py
```

`data/sample_races.csv` が生成されます。出力には `finish_position` と `target_win` も含まれますが、これらは正解・評価用の結果情報です。

### 2. モデル学習と評価

```powershell
.venv\Scripts\python.exe src\train_model.py
```

古い日付から新しい日付の順にtrain → valid → testへ時系列3分割して学習します。**testはモデル調整（設定選択・早期終了の判定）に使用しません。** コンソールに各期間と評価値を表示し、`artifacts/` には学習済みモデル、評価値（回収率・95%信頼区間・較正指標を含む）、test予測が生成されます。既定では `--model-config new`（Phase Aでvalidの指標のみを使って選んだLightGBM設定）で学習します。

```powershell
.venv\Scripts\python.exe src\train_model.py --model-config legacy
```

`--model-config legacy` を指定すると、v0.1と同じLightGBM設定で学習できます。

```powershell
.venv\Scripts\python.exe src\train_model.py --compare
```

`--compare` を指定すると、legacy/new両設定を同一のtrain/valid/test分割で評価し、`artifacts/model_config_comparison.json` へ比較結果を保存します（このとき `artifacts/metrics.json` など学習成果物は更新しません）。

### 3. Streamlit起動

```powershell
.venv\Scripts\python.exe -m streamlit run app.py
```

表示されたローカルURLをブラウザで開きます。停止するときはPowerShellで `Ctrl+C` を押します。

## 評価指標

- **ROC-AUC:** 1着馬を非1着馬より高く順位付けできているかを見る指標です。0.5付近がランダム相当です。
- **Log Loss:** 二値分類の確率予測が正解からどれだけ外れたかを見る指標です。小さいほど良い値ですが、サンプルデータの値を実運用精度として解釈できません。
- **Top-pick accuracy:** 各testレースでAI暫定推定勝率が最も高い馬が、実際に1着だった割合です。モデル全体を評価する唯一の指標ではありません。
- **回収率シミュレーション（架空データ）:** testレースについて、AI予想1位・1番人気それぞれの単勝100円購入を仮定した場合の的中率と回収率を算出します。回収率の95%信頼区間は、レース単位の復元抽出bootstrap（固定seed、2,000回）で求めています。これは架空データ上の購入シミュレーションであり、実競馬での収益性や的中を示すものではなく、購入を推奨するものでもありません。
- **確率較正の確認用指標:** AI予想1位について、表示している推定勝率の平均と実際の勝率の差を算出します。差がゼロに近いほど、表示確率と実際の勝率が近いことを意味しますが、モデルの精度そのものを示す指標ではありません。

## AI暫定推定勝率について

LightGBMは各出走馬を1行ずつ独立した二値分類として扱い、`predict_proba` でraw probabilityを出します。その値は、そのまま厳密な競走勝率とは断定できません。

画面の「AI暫定推定勝率」は、**LightGBMのraw probabilityを `race_id` 単位で正規化し、レース内合計を100%にした表示用の暫定値**です。市場暗黙確率は `1 / 予想時点オッズ`、`value_gap` はAI暫定推定勝率との差です。

`1 / odds` は競馬市場の控除を含むため、同一レース内の合計が100%を超える場合があります（今回のtestデータでは平均約118.2%）。一方、AI暫定推定勝率は合計100%へ正規化されています。そのため `value_gap` は厳密に同一基準へ正規化した比較値ではなく、構造上マイナス方向へ偏りやすい参考値です。`value_gap > 0` であっても、購入推奨や購入した事実を意味しません。

なお、予想時点オッズは結果確定前に利用できる情報としてモデル特徴量にも含めています。そのため、AIと市場の比較は完全に独立した比較ではありません。

## 未来情報を使わない設計

- 特徴量は `src/train_model.py` のリストで明示的に許可しています。
- `finish_position` と `target_win` は特徴量から除外しています。
- `horse_number`（馬番）は、架空データ上で結果と意味のある関係を持たないため特徴量から除外しています。将来の実データ版で馬番を恒久的に使わないという意味ではありません。
- 過去成績の特徴量は、サンプル生成時にそのレースより前の結果だけから計算し、レース終了後に履歴を更新します。
- `race_date` の古い期間から順にtrain → valid → testへ時系列3分割し、ランダム分割は行いません。testはモデル調整（設定選択・早期終了の判定）に使用していません。
- 1レースの結果を見て予想ルールを自動変更する処理はありません。

## ファイル構成

```text
keiba-ai-prototype/
├─ .gitignore
├─ README.md
├─ requirements.txt
├─ app.py
├─ data/
│  └─ sample_races.csv
├─ src/
│  ├─ generate_sample_data.py
│  ├─ train_model.py
│  └─ evaluation.py
└─ artifacts/
   ├─ metrics.json                   # 学習時にローカル生成（Git管理対象外）
   ├─ model.joblib                   # 学習時にローカル生成（Git管理対象外）
   ├─ test_predictions.csv           # 学習時にローカル生成（Git管理対象外）
   └─ model_config_comparison.json   # `--compare`実行時にローカル生成（Git管理対象外）
```

`artifacts/` 配下の各ファイルは `src/train_model.py` の実行時（`model_config_comparison.json` は `--compare` 実行時）に生成され、`.gitignore` によりGit管理対象外です。公開リポジトリをcloneした直後には存在しないため、上記の手順でデータ生成と学習を行ってください。`app.py` は、`metrics.json` が存在しない場合に加え、存在していても本バージョンが必要とするキー（`valid_start` や `betting` など）を欠く旧形式の場合も、架空データから再学習してartifactsを生成し直します。主要な評価結果はこのREADMEにも記録しています。

## 今後の拡張

データ生成、学習、表示を分離しているため、将来は `data/sample_races.csv` と同じ役割の入力をJRA-VAN由来のデータ変換処理へ差し替えられます。その際も、予想時点で取得できる列だけを特徴量にし、結果情報と時系列境界を厳密に管理する必要があります。現在はJRA-VAN / JV-Linkを導入・接続していません。
